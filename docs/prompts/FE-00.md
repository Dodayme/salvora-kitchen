# Script FE-00 — Audit visual/aset dan pemetaan halaman–API

Kerjakan **FE-00 saja** pada proyek Salvora Kitchen. Backend BE-00–BE-14 telah diterima untuk lokal/Sandbox dengan batas yang dijelaskan pada laporan validasi. Tahap ini menyiapkan implementasi frontend, bukan membangun seluruh halaman sekaligus.

## Baca terlebih dahulu

1. Instruksi `AGENTS.md` yang berlaku jika ada.
2. `PRD-Salvora-Kitchen.md` versi aktif; baseline script ini **1.9**, terutama bagian 7, 12, 15, 24 dan 25.
3. `docs/API-CONTRACT.md` baseline **0.13** dan `docs/FRONTEND-HANDOFF.md`.
4. `docs/BE-VALIDATION-FOR-FE.md` dan `docs/TASKS-FRONTEND.md`.
5. Domain docs yang diperlukan: AUTH, CATALOG, BUYER, CHECKOUT, PAYMENTS, ORDERS, REVIEWS, DASHBOARD dan VOUCHERS.
6. Struktur frontend saat ini di `src/app` dan `src/components`, tanpa membaca/menampilkan nilai rahasia.

Jika versi dokumen sudah berubah, gunakan versi aktif dan catat perbedaannya; jangan menimpa perubahan baru dengan baseline lama.

## Tugas

### 1. Audit halaman P0

Buat matriks yang memuat:

- Nama halaman dan route UI usulan.
- Role yang boleh mengakses.
- Sumber desain: frame/PNG, rancangan tambahan mengikuti pola yang ada, atau belum tersedia.
- Tujuan dan komponen utama.
- Endpoint serta metode yang benar-benar ada pada kontrak.
- State loading, kosong, error, sukses, sesi hilang, konflik dan pembayaran belum pasti yang relevan.
- Koreksi terhadap desain awal serta dependensi task FE.

Cakup beranda, katalog/detail, auth, keranjang/alamat, voucher, checkout, pembayaran/finish, riwayat/detail/review, admin dashboard, produk/kategori/foto/stok, pesanan/pembayaran, voucher tetap dan akun sendiri.

### 2. Audit komponen dan aset

Inventaris logo, hero, foto produk, banner, ilustrasi auth, ikon, font serta pola tema/layout. Catat file yang benar-benar tersedia, penggunaannya, sumber, dan kebutuhan pengganti. Screenshot halaman bukan aset foto produk individual.

Bedakan aset siap, kurang, placeholder, dan konten demo. Pertahankan desain hangat oranye/krem/cokelat dengan fotografi makanan, judul serif dan komponen shadcn bertema. Nilai warna/font yang diusulkan harus dibedakan dari hasil inspeksi Figma.

### 3. Selaraskan aturan integrasi

- Next.js + React, Tailwind CSS + shadcn/ui; styling manual tidak menjadi pendekatan utama.
- Katalog publik; transaksi BUYER; admin tidak checkout/review sebagai buyer.
- Voucher 20% maksimal Rp100.000 sekali akun, bukan minimum belanja Rp100.000.
- Delivery manual seluruh Kota Tanjungpinang Rp10.000; deadline pembayaran **60 menit**.
- Quote lima menit tidak mereservasi stok. Konfirmasi order menggunakan quoteId dan Idempotency-Key stabil untuk satu tindakan.
- Status pembayaran hanya dari server; Snap callback/finish/close tidak membuktikan sukses atau gagal. Reconcile bukan polling gateway otomatis setiap render.
- Form registrasi membutuhkan password dan confirmPassword. Profil admin hanya name yang dapat diedit.
- Transisi admin memakai expectedStatus; COMPLETED membutuhkan receiptConfirmed=true dan note dari konfirmasi operasional.
- Pembaruan stok memakai expectedUpdatedAt; foto maksimum 2.000.000 byte sesuai kontrak.
- Jangan membuat COD, rekening transfer manual, pickup, promo umum, CMS, ekspor, preferensi notifikasi, moderasi, atau analitik lanjutan dari gambar saja.

### 4. Susun prioritas dan gap

Kelompokkan gap yang menghambat FE-01, gap yang bisa memakai placeholder terlabel, dan gap penerimaan UI/provider/deployment. Setiap gap memiliki tindakan berikutnya tanpa otomatis menambah cakupan PRD.

## Keluaran

1. `docs/FE-DESIGN-AUDIT.md`: matriks halaman–role–API–state, komponen bersama, koreksi desain, gap, dan urutan implementasi.
2. `docs/FE-ASSET-INVENTORY.md`: inventaris aset yang diverifikasi dan daftar yang masih diperlukan.
3. Perbarui status FE-00 pada `docs/TASKS-FRONTEND.md` hanya berdasarkan kriteria yang benar-benar terpenuhi; sertakan catatan hasil dan kesiapan FE-01.

## Batas pekerjaan

- Tidak membuat seluruh frontend, memasang dependency, merombak backend, atau mengubah schema/config/task Windows.
- Tidak membuat/membayar transaksi Midtrans, memakai ulang referensi lama, menjalankan migrasi/seed/cleanup database, atau membuka rahasia.
- Pemeriksaan tambahan cukup yang diperlukan untuk audit. Tidak perlu mengulang suite database atau provider untuk membuktikan pembacaan desain.
- Jangan menandai halaman implementasi selesai hanya karena audit/mapping tersedia.

## Kriteria selesai

- Semua halaman P0 terpetakan ke kebutuhan serta API aktual atau gap yang eksplisit.
- Setiap aset terdaftar sesuai bukti yang tersedia; akses Figma yang gagal tidak disembunyikan.
- Koreksi admin/pelanggan mengikuti PRD, tanpa penambahan fitur diam-diam.
- FE-01 memiliki arahan tema, komponen dan API client yang dapat dikerjakan.
- Ringkasan akhir menyebut dokumen hasil, temuan utama, keterbatasan, dan task berikutnya.
